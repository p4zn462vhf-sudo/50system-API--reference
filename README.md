# 接口文档概述

欢迎使用 **\[XQ6钱包系统]** Open API 接口服务。本文档旨在为商户及开发者提供全面、规范的 API 集成指南，协助技术团队快速完成系统对接与业务上线。

***

### 1. 系统架构与交互流程

本平台采用基于 **HTTPS/JSON** 的标准 API 协议，提供高可用、高并发的数字资产/支付结算服务。

#### 核心交互流程

1. **认证与签名**：商户请求前需进行安全签名（RSA），校验身份合法性。
2. **异步回调机制**：针对充值、提现等延时类交易，系统提供 HTTP/HTTPS 异步通知（Webhook）服务，确保数据终态可达。
3. **状态对账**：针对网络波动或通知未达场景，商户系统应以主动查询接口（`*.query`）的结果作为兜底判定依据。

***

### 2. 接口能力规范

| 业务模块      | 编码前缀               | 核心能力说明                          |
| --------- | ------------------ | ------------------------------- |
| **账户管理**  | `acct.*` / `wap.*` | 提供账户余额查询、进入钱包 H5 链接生成、用户提币地址获取。 |
| **充值服务**  | `deposits.*`       | 支持深度集成的商户充值下单、状态主动查询及结果异步通知。    |
| **提现/提币** | `withdraw.*`       | 支持商户发起提现/提币申请、提现状态链路追踪及结果推送到账。  |
| **代币空投**  | `airdrop.*`        | 支持批量/单笔代币空投下单、执行状态查询及终态通知。      |

***

### 3. 请求与响应标准

* **传输协议**：仅支持 `HTTPS` 协议，默认请求端口为 `443`。
* **数据格式**：请求与响应 Header 必须设置 `Content-Type: application/json; charset=UTF-8`。
* **业务数据报文**：
  * 请求与响应报文内部核心业务参数放入 `data` 节点中，序列化为 JSON 字符串格式传输。
  * 含有双引号的 JSON 字符串必须进行标准的转义处理（如 `\"key\":\"value\"`）。

***

### 4. 通用应答码与交易状态

* **接口层（retCode）**：
  * `000000`：仅代表**接口请求受理/通信成功**，不代表最终业务成功。
  * 其他代码（如 `900002`）：代表请求被拦截（参数检验失败、风控阻断等）。
* **业务层（status）**：
  * 交易最终状态以业务报文中的 `status` 节点为准（如 `100` 代表交易成功）。

***

### 5. 对接安全与最佳实践

1. **幂等性保障**：商户提交订单时，必须保证 `merchOrderNo`（商户单号）的全局唯一性，防止重复下单。
2. **签名验签**：商户发送请求前需生成 `signMsg`，收到异步通知后必须对报文进行验签，防止数据被篡改。
3. **超时与重试**：建议接口请求超时时间设置为 **5秒 \~ 10秒**；收到未知异常（`999999`）时，**禁止盲目重试下单**，须先调用 `*.query` 接口查询订单真实状态。
